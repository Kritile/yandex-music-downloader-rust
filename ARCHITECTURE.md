# Архитектура

Проект состоит из одного Cargo-пакета и одного исполняемого файла `yandex-music-downloader`. Рабочая программа не запускает Python или FFmpeg.

## Поток загрузки

1. `cli` разбирает аргументы, выбирает источник и проверяет ссылку.
2. `api::MusicClient` получает метаданные треков и альбомов через HTTP API Яндекс.Музыки. Для исполнителя он обходит страницы альбомов, для плейлиста — запрашивает треки пачками.
3. `paths` подставляет поля трека в шаблон относительного пути и очищает компоненты имени.
4. `api` получает подписанную информацию о файле; `download` выбирает контейнер и расшифровывает поток AES-CTR при наличии ключа.
5. `tags` записывает теги и обложку. `download::write_atomic` публикует файл только после успешной обработки временного файла.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `model` | Минимальные модели ответов API, используемые программой |
| `cli` | Параметры, значения по умолчанию, ссылки на источники |
| `api` | Авторизованные запросы, повторы, подписи, выбор коллекций и загрузка байтов |
| `paths` | Шаблоны, очистка и длина компонентов пути |
| `download` | Форматы, AES-CTR и временные файлы |
| `tags` | Метаданные MP3, FLAC и M4A |

Токен передаётся в заголовке только для домена API. Запросы к CDN и серверу обложек выполняются без токена. Программа обрабатывает треки последовательно. Внешний API неофициальный и может меняться; модели игнорируют неизвестные поля ответа.

## Проверки

`cargo test --all-targets` проверяет пути, ссылки, шифрование и запись тегов в файлы из `tests/fixtures`. Перед выпуском также запускаются `cargo fmt --all -- --check` и `cargo clippy --all-targets -- -D warnings`. Для проверки реальной загрузки нужен токен и доступ к сервису.
